hybridx_apply.py 要定义的参数

场景现在只填八张表：落点、机器人、能力、动作、设施、通信、任务、生成图，外加一个随机种子。前置、后置和执行图由 compile_case 按任务类型生成。下面仍是这些表展开之后每个字段的含义和当前取值。单位是米；表里的朝向用度，装配时换成弧度。电量、装载量、能力和可靠性都在 0 到 1。

怎么读 名字对齐 落点 机器人 环境 动作 设施与通信 任务 生成图 翻译 求解

怎么读这些标记

求解会改变方案、行程或可行性。记录写在对象上，当前 TaskSolver.solve 不读取；打印、设施计算或以后的可靠性计算才会用到。

标记含义
求解参与分配、接近移动、前置检查或后置写入。
记录必须能写成合法对象，但当前求的是行程，不看这个数。
设施计算segment_effect 或 comm_effect 读取。求解主过程不读。
翻译只进入执行图。求解使用的是任务节点和生成图。

应用文件是具体场景。类型和算法在 hybridx.py。0.1、0.2 的乘积、并行可靠性和增益公式不在应用文件里填数；应用文件提供设施、距离和链路，__main__ 再调用那些公式。

必须互相对上的名字

这些字符串分散在不同节。对不上时，对象要么构造失败，要么求解把能力当成 0，要么依赖找不到。

名字出现位置当前约定
任务类型 ttype 任务、Robot.capability 的键、基元列表、翻译 能力字典的键必须等于任务类型。缺键按 0 处理，机器人不能做这件任务。
角色键 RobotRole、前置 who、后置 ('robot', 键) 无槽时就是机型，如 arm、transport。有槽时是 transport:1。同一任务里键不能重复。
任务编号 tid 任务字典的键、Dependency(ref, 'id') 如 T_load_A。依赖按编号指向时，这个编号必须出现在生成图展开后的节点里。
落点名 Facility.sites、segment_effect 的两端 pit_a、pit_b、gate、stack。它们是名字，不会自动等于坐标常量。
栅格键 env.mat、env.occ、放置的环境效果 字符串 'x,y,z'。当前 z 都是 0，例如建造点是 '2,2,0'。坐标元组 (2.0, 2.0) 不会自动写成这个键。
机型 Robot.rtype、角色、ActBuilder.seq 的第一条参数 只有 transport 和 arm。翻译图里的机型集合必须等于该任务角色的机型集合；槽不参与这个比较，两台运输车仍共用一条运输车动作。
移动词 生成图 steps move、move_ang、deliver、nav、roadtrans。它们写在步骤里，存图时删除，不能登记成基元，也不能做生成图的名字。

机器人

字典 robots 的键是机器人编号。每台机器人是一个 Robot，状态是 TransportRobot 或 ArmRobot。

每台都要填的字段

字段类型与范围谁在用含义
rid字符串，字典内唯一求解分配结果里的机器人编号。同一任务的不同槽必须分到不同编号。
rtypetransport 或 arm求解必须和状态类型一致。运输车才能有装载量和里程，机械臂才能有关节和夹爪。
pos(x, y)，米求解初始位置。接近行程从这里算到任务后置位置。
theta弧度记录朝向。求解的接近移动不改变它。R3 写成 math.radians(90)，数值是 1.5708。
bat实数，约定 [0, 1]求解初始电量。接近移动按 lam_b × 距离 扣电，任务后置再按 add 扣电。低于前置阈值则该方案失败。电量减到负也会失败。
belief字典，默认为空记录初始信念。当前前置不读它。后置用 merge 写入。
capability字典，任务类型 → [0, 1]求解这台车做某类任务的能力。必须大于等于该任务角色上的阈值才合格。相同行程时，搜索更倾向能力高的车。
r0[0, 1]，默认 0.99记录零距离里程计可靠性。当前文件省略，使用默认。设施计算自己也默认 0.99，不读取机器人上的这个字段。
lam_r每米，默认 0.002记录里程计随距离衰减的系数。公式是 r0 · exp(-λ · d)。求解不读。
lam_b每米，默认 0.0005求解接近移动的耗电系数。当前四台都用默认值。

运输车额外字段

字段类型与范围谁在用当前
full[0, 1]，默认 0求解0。装载要求 full <= 0，卸载要求 full >= 1。省略时就是空车。
dis米，默认 0，不能为负记录0。求解接近时会把它加上路程，但优化目标用的是另一份行程累计，不读这个初值。

设施与通信

二者都不是任务节点。定位设施挂在被删掉的移动段上，通信挂在多车同时在场的任务上。求解分配和行程都不读它们。__main__ 用 0.2 的函数计算段可靠性和链路是否闭合。

任务

字典 tasks 的每一项是一个 TaskNode。求解展开 build 之后，按这些节点分配机器人、检查前置、写入后置，并把后置位置当作接近目标。

三个可靠性常数：大物体 _LOW = 0.82，中型 _MID = 0.96，小型 _SMALL = 0.97。记录它们写在节点上并会打印。当前求解优化的是行程，不把步骤可靠性放进目标。

任务节点的字段

字段谁在用含义
tid求解任务编号。按 id 依赖时用它。
ttype求解任务类型。能力字典、基元和翻译都用它。
roles求解角色列表。每项是机型、能力阈值、可选槽。
pre求解前置。接近移动之后检查，不过则方案失败。
post求解后置。其中 pos 决定行程，其余写入状态。
deps求解任务偏序。生成图的边之外，再要求这些前驱先完成。放置 B 依赖放置 A，放置 C 依赖放置 B，垒放顺序靠这里。
reliability记录[0, 1]，默认 1。当前不进入行程优化。

角色 RobotRole

字段含义
rtypetransport 或 arm。
capability[0, 1]。角色阈值。机器人在该 ttype 上的能力必须大于等于它。
slot默认空字符串。空则角色键等于机型。装载 A、卸载 A 用 '1' 和 '2'，键变成 transport:1、transport:2，从而要求两台不同的运输车。

前置 PreCondition

who 里的名字必须是本任务的角色键。一项或两项。op 只能是 < <= > >= ==。value 必须是数，不能写坐标。

写法求解怎么读
一个角色，key 为 bat、full、grip、theta、dis读该机器人状态上的同名数。
两个角色，key='dist'读两台车当前位置的欧氏距离。若比较是 < 或 <= 且尚未满足，两台车先走到中点，这段也计入行程。

后置 PostEffect

字段取值
target('robot', 角色键) 或 ('env',)。
key机器人侧常用 pos、grip、bat、full、belief。环境侧常用 mat、occ。
valuepos 是 (x, y)。bat 的增量是负数。full 写成 0 或 1。grip 写成 0 或 1。belief、mat、occ 是字典。
modeset 覆盖，默认。add 累加，用于电量。merge 合并字典，用于信念、材质、占用。

_pos(who, point) 是简写，等于 PostEffect(('robot', who), 'pos', point)，模式为覆盖。参与任务的每台机器人都写了位置，求解才会把这台车开到该点。

依赖 Dependency

ref 是前驱的编号或类型。by 默认 'id'，也可写 'type'。当前全部按编号。前驱必须已经出现在 build 展开出的图里。

生成图

operad 先登记基元，再登记生成规则，最后 decompose 得到 trees。求解只用 trees['build']。

基元

下面 14 个字符串必须已经是任务类型，并且不能是移动词：

dig_a dig_b load_a load_b unload_a unload_b load_nav_a unload_nav_a grasp_a grasp_b grasp_c place_a place_b place_c

生成规则要填的参数

参数含义
output复杂任务的名字。不能与基元重名，不能是移动词，不能登记两次。
steps有序名字。移动词会删掉。剩下的每一项必须是基元或已经登记的复杂任务。

求解

当前调用是 TaskSolver(robots, env, trees['build'], seed=1)，然后 solve()。先束搜索，再自适应大邻域搜索。目标是总接近行程。

参数当前默认含义
robots上面的四台无默认求解构造时深拷贝。搜索中的耗电和位移不改回应用文件里的原对象。
env上面的环境无默认求解深拷贝。后置材质和占用写在副本上。
graphtrees['build']无默认求解必须是已经展开、并且每个基元都能找到任务的图。节点上的任务不能为空。
seed10求解随机数种子。候选补足和退火都用它。换种子可能换到行程相同的另一组车。
beam_width未写8每一层保留的部分方案数。至少为 1。
robot_limit未写4每个角色最多尝试多少台合格机器人。至少为 1。当前每类合格车不超过 2 台，这个上限没有裁掉任何人。
iters未写120大邻域搜索迭代次数。至少为 1。
destroy_ratio未写0.3每次打乱的分配比例。
T0未写8.0模拟退火初温。
alpha未写0.97每步温度乘上的系数。

以 seed=1 求出现行方案时，行程是 544.67，方案可行。改位置、能力、阈值、槽、依赖或 build 的 deps，这个数和分配都会变。改动作字典、步骤可靠性、设施和通信，行程不变。
